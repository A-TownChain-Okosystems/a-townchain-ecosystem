# A-TownChain Ecosystem — Lifecycle

## DEVNET
Active implementation, integration and failure discovery. Evidence includes component tests, integration tests and CI diagnostics. Production claims are prohibited.

## TESTNET
Multi-node, persistence, recovery, protocol conformance and security validation under testnet conditions. Evidence must be reproducible.

## MAINNET-0
Minimum production-capable trust and execution core. Required: consensus, economics, verifier-gated VM, required cryptographic verification, durable state, node/network behavior, deterministic state transition, recovery, required wallet/SDK transaction path and release evidence.

## MAINNET EXPANSION
Adds L2 capabilities, services, AI providers, interoperability, economic applications and platform features without weakening Mainnet trust invariants.

## FULL ECOSYSTEM
The complete declared product ecosystem, including platform, AI, developer, economic and creation/application capabilities whose contracts and release criteria are satisfied.

## Status vocabulary

- MISSING — required capability has no implementation.
- INCOMPLETE — implementation exists but required behavior is missing.
- DIVERGENT — implementation conflicts with canonical architecture or standard.
- DUPLICATED — multiple competing implementations claim one canonical responsibility.
- UNVERIFIED — implementation exists but required tests, CI or evidence are absent/stale.
- COMPLIANT — architecture, implementation and required evidence agree for the declared lifecycle stage.
- EXPANSION — intentionally deferred beyond the current lifecycle stage.

Documentation or roadmap text alone never upgrades a status.
